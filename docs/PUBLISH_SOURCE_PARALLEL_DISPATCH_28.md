# Эксперимент 28: диспетчер bound requests — отклонён

В реальный Source parser был подключён экспериментальный путь: owner связывает
имена и собирает до 64 простых scalar/link statements, четыре независимых
resolver читают общий Graph, owner применяет результат в исходном порядке.
Неподдерживаемые формы и ошибки возвращаются в канонический parser через replay
уже прочитанных semantic tokens. `identity_ref` и формат файлов не менялись.

## Проверки и измерения

Frontend regressions прошли, включая проверку фактического выполнения более
260 assignments через dispatcher. Девять интеграционных сценариев сохранили
артефакты. Двенадцать ошибочных сценариев дали точную baseline диагностику,
включая раннюю semantic error перед поздним directive, незакрытый индекс,
отсутствующий semicolon и предупреждения перед ошибкой.

Нативный MSVC Release IPO, копия UnitProXL, чередование baseline/candidate,
по одному прогреву на вариант и режим. Каждые два файла проверены SHA-256,
после каждого запуска выполнен независимый audit старым executable.
Сборки и тесты во время замеров не запускались.

| Режим | Пар | Baseline, ms | Dispatcher, ms |
|---|---:|---:|---:|
| Обычный PUBLISH | 3 | 1423.087 | 2302.093 |
| Stage: total | 2 | 1447.900 | 2289.335 |
| Stage: Source | 2 | 491.310 | 1293.485 |

Все 14 запусков, включая прогревы, сохранили эталонные SHA-256 и прошли audit.
Это короткая диагностическая серия, но регрессия слишком велика для принятия:
обычный PUBLISH медленнее примерно на 62%. Stage показывает основную прибавку
в Source. Вероятные причины — частые worker rendezvous на маленьких пачках,
дополнительное хранение/replay токенов и повторные проверки binder. Отдельные
вклады этих причин не измерены, поэтому приписывать всё одной синхронизации нельзя.

## Решение

Диспетчер, его CMake option и временные telemetry fields удалены из рабочих
исходников. Source parser восстановлен побайтно из сохранённой версии до
эксперимента. Bound resolver шага 27 сохранён; production работает последовательно,
construction window остаётся OFF. Логи, CSV, baseline/candidate и исходники
отклонённого прототипа сохранены в `build/publish-source-parallel-dispatch-28/`.

Следующий вариант должен сначала уменьшить стоимость owner binding и выдавать
существенно более крупные независимые порции работы, сохраняя барьеры declarations,
видимость WHO, первую ошибку и порядок commit. Увеличение числа потоков само по
себе не подтверждено как способ достичь PUBLISH < 1 s.
