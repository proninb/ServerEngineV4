# Адреса и указатели в Source Parser V2

Поддержаны `p = &object`, `p = &object.field`, `T* p = &object`, `p = q`,
`*p`, `**p`, `(*p).field` и `p->field`. Ссылка может привязываться к
разыменованному endpoint. Код произвольных выражений C++ не выполняется.

Адрес хранится связью Graph с типизированным путём до целевого подобъекта,
а не адресом процесса в compiled.bin. Материализация восстанавливает адрес.
Проверяются типы, const/volatile, void-указатели и однозначное публичное
преобразование к базовому классу с правильным смещением. Снятие const,
несовместимые типы и неоднозначные/закрытые преобразования отклоняются.

Обновлены Graph, аудит compiled-данных, Fixed Direct и SHM Runtime V2.
Frontend regressions и compiled_project tests проходят. Fixed Direct проверяет
реальные адреса `int*`, `int**` и запись через `**p`. TCP PUBLISH, LOAD и LOAD
в новом процессе подтверждают значение 37, соседнее поле 123 и адреса в памяти.
Результат: `build/unitprotr-pointer-tcp-final/summary.json`.

Ограничения: арифметика указателей и произвольные вычисления не добавлены.
Source строит статическую модель, а не исполняет последовательность операций.
Смешивание литерального присваивания указателю (`p = nullptr`) с адресной
привязкой того же endpoint отклоняется, чтобы не сохранять неверный порядок
перезаписи. Старый синтаксический парсер BUILD не расширялся.

В локальном адаптере UnitProTr `SimLink.From/To` объявлены `void*`: экспорт
использует их для адресов объектов, полей и целых массивов. Массивы не
преобразуются в `SimObject*` по правилам C++. Размер и выравнивание указателей
сохранены, исходный SDK не изменён.

UnitProTr проходит прежние присваивания `TRANSFER.From/To`, базовые ссылки и
преобразование массива в указатель. Актуальная следующая остановка описана
в `SOURCE_BASE_REFERENCE_BINDINGS.md`.
