# Source resolver: первый реализованный срез

Добавлен `parser/source_endpoint_resolver.hpp`. Resolver хранит `const graph&`
и собственные transition/base caches. Он читает тип объекта по WHO, выбирает
bounded array, определяет record/referent и разрешает члены с наследованием.
У него нет доступа к string_table, identity_space, Source Map или mutable Graph;
он не интернирует пути и не записывает связи/инициализации.

Путь Source разделён на `read_endpoint` и последующую канонизацию endpoint path
в `resolve_endpoint`. Последняя всё ещё вызывается немедленно в прежнем порядке:
path handles, записи G, зависимости, предупреждения и первая ошибка сохраняют
свою очередность. Экспериментальный Source Model использует тот же resolver
членов вместо дублирования поиска и кэша. Новый заголовок добавлен в дерево VS.

Parser по-прежнему владеет binding имён, курсором, временным steps buffer,
Source Map и commit. `read_endpoint` целиком ещё не является worker-функцией:
оно продвигает курсор и регистрирует зависимости. Выделенный resolver работает
с read-only каталогом, но const graph не разрешает одновременный рост контейнеров
G другим потоком. Пул workers и bounded assignment windows пока не добавлены.

## Проверки

Расширена регрессия cross-root endpoints. Она проверяет выбор object/array/
reference типов, inherited owner и ancestry, добавление кэшем пути к текущему
локальному prefix, сброс выходных значений при missing member и отсутствие
новых endpoint paths/initializations/links после вызовов resolver.

Дополнительно baseline/candidate сравниваются на семи ошибочных программах:
обращение до объявления, отсутствующий член, индекс вне диапазона, индекс у
скаляра, member access у скаляра, несовпадение reference типов и две ошибки
подряд. Сравнивается точный stderr, а также отсутствие compiled.bin после отказа.

Предварительный вариант прошёл frontend regressions, девять интеграционных
сценариев, семь диагностических сравнений и 24 full-fixture вызова с точными
хешами файлов и независимыми baseline audits. Семь обычных пар дали 1416.199 ms
baseline против 1424.417 ms candidate; отдельные три stage пары — 1432.817 против
1406.577 ms total и 457.774 против 447.707 ms Source. Эти разнонаправленные малые
серии не доказывают ни ускорения, ни стабильной регрессии. После них в resolver
также перенесены read-only object/array/reference type queries.

Финальный вариант проверяется отдельно в `build/publish-source-resolver-24-final/`.
Предварительные бинарные файлы и логи сохранены в
`build/publish-source-resolver-24/`. Изменение структурное; новый выигрыш в скорости
не заявляется. Следующая часть реализации — передача локальных typed endpoint
результатов через ограниченное окно и отложенный последовательный commit.

Финальная сборка прошла все 22 CTest tests, девять интеграционных сценариев и
семь точных диагностических сравнений. Все 14 финальных full-fixture вызовов,
включая warmup, сохранили SHA-256 обоих артефактов и прошли независимый audit.
Три обычные пары дали 1423.487 против 1397.063 ms; две отдельные stage пары —
1454.620 против 1409.220 ms total и 490.026 против 455.437 ms Source. Серия мала,
baseline содержит медленные запуски; подтверждённое ускорение из неё не следует.
